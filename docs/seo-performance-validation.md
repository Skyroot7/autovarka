# SEO и производительность: изменения и проверка

Дата: 13 ноября 2026. Исходная версия: `6a9b88b82a2cb15249d6e675af6e88174cf0481d`.
Ветка: `seo/catalog-performance`. Production-деплой и merge не выполнялись.

## Контракт каталога

- Единственный источник production-каталога — настроенный Vercel KV. Чтение больше не пишет в KV и не восстанавливает товары из старого JSON.
- Публичный снимок проходит проверку структуры, уникальности ID, цены, наличия, изображений и языковых полей. Успешно прочитанный пустой массив остаётся пустым.
- Next Data Cache ревалидируется через 30 секунд. Абсолютный предел возраста подтверждённого снимка — 60 секунд; проверка выполняется **вне** кеша, поэтому stale-if-error не превращается в бессрочную подстановку.
- Ключ кеша разделён по хешу endpoint KV. React cache объединяет чтения одного рендера; одновременные live-запросы объединяются отдельно.
- Отсутствующий в кеше ID перепроверяется живым запросом перед разрешением `notFound()`. Сбой чтения не означает отсутствие товара.
- При отсутствии достоверных данных API возвращает 503 с Retry-After, sitemap — временную серверную ошибку, публичные страницы завершаются ошибкой до отправки HTTP 200. Корзина, профиль, контакты и административные страницы не зависят от этой предварительной проверки.
- Корневой layout использует только внутренний маркер публичного маршрута, который middleware перезаписывает. Правила canonical/hreflang и локализации не изменены.
- Только локальная разработка без обеих KV-переменных использует JSON из репозитория. Production не подменяет базу этим файлом. Холодный запуск во время отказа KV без проверенного снимка не гарантирует доступность витрины; он корректно завершается серверной ошибкой.
- Административное редактирование требует действующей серверной сессии и свежего чтения KV. Кеш/резервный снимок не используются для подготовки записи. После успешного сохранения сбрасывается публичный тег, sitemap и layout. Ошибка инвалидации не объявляет уже выполненную запись неудачной.
- Схема хранения товаров и существующий механизм записи всего массива сохранены. Конкурирующее редактирование несколькими администраторами по-прежнему требует отдельного решения атомарности; миграция хранилища не выполнялась.

## SEO и интерфейс

- Каталог и рекомендуемые товары передаются сервером. Названия, цены и обычные ссылки существуют без JavaScript.
- Product/BreadcrumbList/Organization/WebSite выводятся серверными JSON-LD script без конфликтующих ID. Содержимое безопасно сериализуется; данные меняются вместе с текущей карточкой.
- Общий нормализатор изображений сохраняет абсолютные Blob URL и корректно дополняет относительные пути. Offer/ItemList используют текущую локаль.
- Наличие, обработчики покупки, кнопки и Offer согласованы. Данные и ID реальных товаров не редактировались.
- Главная и Footer — Server Components. Поиск получает каталог только при открытии и пересчитывает результаты при поступлении данных.
- Первый экран не скрывается до гидратации. Для оставшихся анимаций каталога используются LazyMotion и prefers-reduced-motion; CSS-hover сохранён.
- Главное изображение карточки и hero имеют preload; остальные изображения lazy. Разрешённые Blob-изображения оптимизируются через Next Image; добавлена поддержка AVIF/WebP и действительная SVG-заглушка.
- Неиспользуемый Inter удалён; существующий Arial сохранён. YouTube получает постер и iframe только после нажатия, с постоянным соотношением сторон.
- Отсутствует общая принудительная динамичность языкового layout. Публичный каталог остаётся SSR, чтобы HTML не сохранял бессрочно старые коммерческие данные; кешируется ограниченный по свежести слой данных.

Браузер: 27 групп проверок прошли, 0 page errors и 0 запросов изменения данных:

- SSR без JavaScript на украинском, русском, английском, польском и немецком; 10 товаров, соответствующие названия/цены/ссылки.

- Галерея; корзина: добавление, количество, сохранение после reload и удаление.
- Форма заказа: обязательные поля, необязательный email, три способа оплаты, нативная проверка заполнения и отмена; без отправки заказа.
- Административная форма входа и обязательные credentials; неавторизованные session/orders возвращают 401. CRUD и инвалидация проверены unit-тестами на заглушках, не в рабочей базе.
- Отдельный fixture с `inStock:false`: надпись/Schema.org согласованы, обе кнопки отключены на пяти языках, синтетические клики не меняют корзину.
- Поиск с задержкой API 500 мс, видеопостер, iframe после нажатия, reduced motion, мобильная/десктопная геометрия без горизонтального переполнения.

При искусственном отказе KV проверены: свежий снимок продолжает обслуживаться; после 32 секунд API помечает резервные данные; после предела возраста API503/sitemap5xx; после восстановления API200. Дополнительная проверка холодного отказа после защиты от streaming подтверждает HTTP500 публичных товарных страниц, API503 и доступность cart/admin с HTTP200, даже при поддельном входящем маркере.

Украинский цикл был связан с запуском Next с `--hostname 127.0.0.1` и несовпадением origin внутреннего rewrite. Та же сборка с `--hostname localhost` или стандартным bind возвращает украинские URL с 200 и нормализует `/uk/*` одним перенаправлением. Правила перенаправлений не переписывались.

## Повторение проверок без рабочей базы

```bash
npm ci
npm test
npx tsc --noEmit
npm run lint
npm run build
```

Для браузера запустить в отдельных терминалах:

```bash
node tests/fixtures/kv-server.mjs
```

```bash
# Только локальный readonly fixture; значение токена фиктивное.
KV_REST_API_URL=http://127.0.0.1:3400 KV_REST_API_TOKEN=local-fixture \
  npm start -- --hostname localhost --port 3200
```

Браузерный тест использует Playwright Core и установленный Chromium. Инструмент можно установить вне проекта:

```bash
npm install --prefix /tmp/autovarka-browser-tools --no-save playwright-core
PLAYWRIGHT_MODULE_PATH=/tmp/autovarka-browser-tools/node_modules/playwright-core/index.mjs \
  BASE_URL=http://localhost:3200 npm run test:browser
```

Тест ограничен loopback, блокирует внешние адреса и запросы изменения данных. Fixture отклоняет команды Redis, кроме GET. Для отдельного out-of-stock сервера использовать `KV_FIXTURE_PORT=3401`, его локальный `/__out_of_stock` и отдельный процесс приложения с соответствующим KV URL. Служебные URL fixture не являются частью приложения и не должны публиковаться.

## Ограничения

Рабочая база, production-переменные, заказы и реальные уведомления не изменялись. `lib/products.ts`, `lib/productsData.json`, `lib/orders.json`, исходные фотографии и lockfile сохранены.

Не выполнялись реальные вход/сохранение в production-админке, отправка заказа, почты/Telegram и внешнее воспроизведение YouTube. Перед merge нужны проверки авторизованного CRUD и оформления на отдельной тестовой базе, а также соответствия реального KV ожидаемой схеме.

Нет Search Console, Merchant Center, CrUX или реального p75 INP/LCP/CLS. Локальный Lighthouse не подтверждает достижение целевых полевых Core Web Vitals. Измерения ниже используют production build, одинаковый readonly fixture, Chromium 156 и Lighthouse 13.6; внешние YouTube/analytics блокировались одинаково. Это ограниченные синтетические прогоны, не SLA и не реальные пользовательские данные.

## Lighthouse до и после финальных изменений

Мобильные измерения (значения до → после):

| Страница | Performance | LCP, мс | TBT, мс | TTFB, мс | Передано JS, байт |
|---|---:|---:|---:|---:|---:|
| Главная | 72 → 94 | 3947 → 2841 | 630 → 134 | 34 → 25 | 228054 → 170055 |
| Каталог | 79 → 96 | 4245 → 2820 | 315 → 44 | 27 → 18 | 227832 → 203267 |
| Карточка | 87 → 95 | 3733 → 2374 | 104 → 190 | 45 → 48 | 227693 → 172741 |

Desktop Performance: главная 100→100, каталог 95→100, карточка 100→100. Desktop LCP после: 667/668/653 мс; TTFB: 24/18/28 мс. Во всех финальных прогонах CLS=0.

TBT карточки в финальном мобильном прогоне вырос примерно со 105 до 190 мс; это отмеченная лабораторная регрессия, несмотря на уменьшение JS и улучшение LCP. TBT не является измерением INP. Мобильный LCP главной и каталога остаётся около 2,8 с, поэтому даже лабораторный ориентир 2,5 с пока не достигнут для этих страниц. Полевые цели не подтверждены.

Каждая таблица использует один сопоставимый финальный прогон на страницу/устройство. Кеши сервера и изображений предварительно прогреты; Lighthouse очищает браузерный кеш. Холодная конвертация AVIF отдельно не измерялась. Повторные промежуточные измерения колебались; в таблицу не выбирались лучшие промежуточные результаты. Производственная сеть/CDN, пользовательские устройства и внешние интеграции здесь не измерялись.
